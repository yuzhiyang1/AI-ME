规则、工具、权限、环境、窗口身份

所以更准确的名字是：Agent 管理的外部记忆 + 上下文窗口轮换。它没有让摘要模型把旧对话压成一段文字。

02 · THREE KINDS OF STATE

先把信息分成三类

🫧
临时

Window Messages

本窗口的用户消息、模型回答、工具调用结果。切窗后不会自动进入新窗口。

📚
持久

Notes + History

Notes 是 Agent 主动整理的可写记忆；History 是按窗口和 item 保存的只读事实。

🧭
重建

World State

模型指令、AGENTS.md、权限、工具、插件、环境、协作模式和窗口 ID 等当前状态。

公开模型配置示例：剩余 6144 tokens 时提醒；基础自动压缩线之后还预留 16384 tokens 的 fallback buffer，专门给“写最后一份 notes + 切窗”使用。数值是模型配置，不是架构常量。

主动切换

new_context 做了什么？

工具调用只设置“请求新窗口”标志并返回：新窗口将启动，而且不会总结旧历史。当前采样步骤结束后，Agent Loop 看到该标志，再执行窗口切换。

兜底切换

Agent 忘记写 notes 呢？

基础预算归零时，Codex 可注入强制提示：只允许做一次 notes 写入，然后调用 new_context。如果连缓冲也耗尽，则自动开启新窗口。

04 · MEMORY TOOLS

Notes 和 History 是两种不同记忆

NotesHistory
性质Agent 主动整理的工作记忆系统保存的原始事实索引
可写性write / append / read / search只读 list / read / search
适合放目标、决定、进度、踩坑、下一步旧用户原话、工具结果、某次动作证据
定位方式虚拟 note pathagent + window ID + item ID
一致性成功写入后读取立即可见；列表/搜索最终一致只读但最终一致，刚产生的 item 可能稍后才可搜到
限制每个 note 文件最多 1,000,000 UTF-8 bytesread_item 必须分页指定字符 offset/limit

关键设计：notes 不应该复制整个历史，只保存“索引卡”。需要证据时，用记录下来的 window ID + item ID 去 history 精确读取。

05 · WHAT SURVIVES

新窗口里自动带回什么？

自动重建
  • 基础模型与开发者指令
  • AGENTS.md 与项目约束
  • 工具、插件、应用能力
  • 权限和执行策略
  • 环境与协作模式
  • First / Previous / Current Window ID
  • 可选 thread hint
不会自动带回
  • 旧窗口的完整用户对话
  • 旧模型回答与推理过程
  • 旧工具结果正文
  • 未写入 notes 的隐含计划
  • 只存在于模型短期注意力里的细节

切换时，start_new_context_window 会推进窗口编号和 UUID，构造最新 World State，把活动历史替换为新的 initial context，并持久化一个 CompactedItem。环境本身不会被清空：文件、进程、Git 工作区等仍按原状态存在。

06 · WHY

为什么有人会选它，而不是自动摘要？

收益
  • 避免一次摘要把错误永久固化
  • 旧事实仍可按需精确找回
  • 活动上下文重新变得很小
  • Agent 能持续维护真正有用的工作记忆
  • 天然支持多个窗口和多个 Agent 身份
代价
  • 高度依赖 Agent 是否及时写好 notes
  • notes 可能过期、矛盾或遗漏
  • 恢复要额外调用检索工具
  • History/Notes 后端成为关键依赖
  • 提示词纪律和模型能力要求更高
