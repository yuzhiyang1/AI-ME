# 代码检查

1. 先读取项目约定和 Git 状态，确定用户要求的检查范围。
2. 读取相关改动及调用方，重点检查输入边界、失败路径和兼容性。
3. 只报告有明确触发条件的问题，给出文件位置、影响和修复建议。
4. 需要验证时，使用项目已有测试命令。执行仍服从当前会话权限。
5. 测试不可运行时说明具体原因；没有发现问题时明确说明已检查范围。
6. 上下文换窗前保存检查进度、未完成项，以及本 Skill 的 ref 和 version。

不要把猜测写成已确认缺陷，也不要声称执行了未运行的测试。
