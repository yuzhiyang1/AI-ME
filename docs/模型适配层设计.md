# 模型适配层设计

## 目标与边界

模型适配层为 AI-ME 自研 Python Agent Runtime 提供统一的大模型调用能力。应用层只认识稳定的消息、请求和 Provider Event；厂商 SDK、认证、API 协议与兼容差异全部留在基础设施层。

当前仅支持两类协议：OpenAI Chat Completions 与 Anthropic Messages；内置 OpenAI、DeepSeek、Anthropic 三家厂商。DeepSeek 与 OpenAI 共用协议适配器，验证“新增兼容厂商只增加目录配置”的扩展路径。

Pi 等开源 Agent 项目曾作为早期调研材料，但 AI-ME 不依赖其代码、运行时或兼容协议。后续 Runtime Kernel 由本项目按自身业务需求演进。

## 依赖方向

```text
presentation/api
  -> application/models 用例
    -> application/ports/model_gateway.py
      <- infrastructure/llm/model_gateway_impl.py
        -> catalog.py + 协议适配器 + 厂商 SDK
```

- 应用层拥有 `ModelGateway` 端口以及稳定的请求、消息和流事件契约。
- 基础设施层拥有 `ApiKind`、厂商目录、API key 来源和协议适配器。
- `ModelDescriptor` 不含 `ApiKind`，避免传输协议泄漏进应用层。
- Presentation 只调用应用用例，不直接调用基础设施实现。

## 请求契约

`LlmCompletionRequest` 包含：

- `model_ref`：`provider/model_id` 格式的模型引用；
- `messages`：只允许 `user` 与 `assistant`；
- `system`：系统提示词的唯一来源；
- `max_tokens`、`temperature`：可选采样参数。

把 `system` 与普通消息分开，可防止 OpenAI 出现两个系统提示词，也避免 Anthropic 静默丢弃消息级 system。具体落位由协议适配器处理。

## Provider Event

模型 SDK 的流式分块先被翻译为以下瞬态事件：

- `LlmStreamStarted`
- `LlmTextDelta`
- `LlmThinkingDelta`
- `LlmToolCallDelta(index, call_id, name, arguments_delta)`
- `LlmStreamCompleted(finish_reason, usage)`
- `LlmStreamFailed(error)`

结束事件保留停止、长度截断、工具调用、内容过滤等原因，并携带厂商返回的 token 用量。错误事件包含类别、稳定错误码、消息和 `retryable`，供未来 Agent Runtime 决定重试、降级或请求人工处理。

Provider Event 不是产品级 Runtime Event。前者是单次模型调用的瞬态协议；后者将记录 Agent Run、工具执行、审批、证据和恢复点。未来由 Runtime Kernel 把 Provider Event 消费并转换成可持久化的运行事实，避免把 SDK 细节写入业务事件日志。

## 请求期错误与流中错误

- 未知或未配置的模型属于请求期错误，由 `StreamModelCompletion` 在创建流之前校验，开发诊断接口返回 HTTP 404。
- SDK 连接建立后出现的错误属于流中错误，由协议适配器转换成 `LlmStreamFailed` 并终止流。
- 401/403、429、超时、连接失败、5xx 与其他 4xx 会被归一化，并明确是否建议重试。

## 开发诊断接口

```text
GET  /api/models
GET  /api/settings/models
POST /api/settings/models
POST /api/dev/chat/completions
```

桌面用户优先通过设置页新增模型。非敏感元数据由 SQLite 和 Alembic 管理，API Key 以配置 ID 为索引写入操作系统凭据保险库；读取接口只返回 `credentialStored`，不返回密钥。保存或轮换同一模型引用后，动态网关立即替换运行时，无需重启。环境变量装配继续用于自动化部署和开发场景。

`/api/dev/chat/completions` 只用于验证模型配置和 Provider Event 翻译，不是 AI-ME 的产品聊天入口。正式产品能力必须由 Agent 用例暴露，例如未来的 `StartAgentRun`、`ResumeAgentRun`，不能绕过 Runtime Kernel 直连模型。

## 扩展方式

代码内置新的 OpenAI 兼容厂商：

1. 在 `catalog.py` 增加 `ProviderDefinition`；
2. 配置独立的 `AIME_*_API_KEY` 环境变量；
3. 增加目录与路由测试。

普通用户无需修改目录代码，可在设置页选择“OpenAI 兼容服务”并填写厂商标识、模型 ID、API 地址和密钥。

新增一种 API 协议：

1. 在基础设施层 `ApiKind` 增加枚举；
2. 新建协议适配器并完整翻译工具调用、结束原因、用量和错误；
3. 在装配根增加显式分支；
4. 用 SDK 假对象覆盖流事件测试，再增加可选的真实冒烟测试。

装配对未知协议采用失败关闭策略，不会默认误路由到某个现有适配器。

## 当前验证

- OpenAI：system 落位、thinking、text、tool call、finish reason、usage、结构化错误；
- Anthropic：独立 system、tool use、增量 JSON、stop reason、usage；
- Gateway：厂商路由、未知模型结构化错误、模型引用唯一性；
- HTTP：旧通用 chat 路由不存在、消息非空、system 不能混入 messages、未知模型返回 404；
- 架构：Domain/Application 不依赖外层框架或基础设施。

仍需在真实 key 环境补充厂商冒烟测试，并在 Runtime Kernel 出现后覆盖取消、超时、重试与工具调用拼装的端到端行为。
