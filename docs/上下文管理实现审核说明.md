## 当前实现选择

- 使用保守的 UTF-8 字节估算及协议余量，UI 明确标识估算；尚未接入特定模型 tokenizer 或在线计数 API。代价是可能提前换窗。
- 每个 Run 最多 32 次模型请求，维护与溢出重试均计数并持久化；换窗不重置步骤和审批。
- Checkpoint 上限 12000 UTF-8 字节，六项任务字段及 history item 引用；工具和产物引用通过对应历史条目追溯。换窗前再次校验完整请求是否容纳得下。
- 单产物采集上限 16 MiB，会话产物配额 128 MiB；并行采集预留空间。达采集上限后继续排空命令管道并标记不完整，达配额则返回明确错误。
- Artifact 正文与 JSON 元数据保存在专用本地目录；T2 账本记录产物引用。元数据未另建 SQLite 表，文件发布成功后才允许引用进入工具完成记录。
- `artifact_read` 使用字节游标并保持 UTF-8 分页边界；`history_read` 使用字符游标。均由服务端强制上限。
- 保存新窗口基线、切换活动窗口和换窗事件处于同一事务。最终回答也记录完成标志，避免回答落盘后、UI 投影提交前崩溃导致重新请求模型。
- 工具执行前保存完整调用批次及允许工具集合；部分 T1 尚未写入时崩溃也能恢复剩余调用，已完成 T2 只复用。已产生的不确定结果审批始终读取最新状态，Session 授权不能跳过它。
- 历史范围未被笔记覆盖时，新窗口携带不完整标记与检索入口。这不是语义无损保证，接续质量仍需真实模型任务评估。
- 不自动清理已发布产物；孤立发布文件也计入配额，避免误删仍被账本引用的结果。清理策略可后续独立演进。
