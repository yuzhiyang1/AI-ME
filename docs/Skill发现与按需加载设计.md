# Skill 发现与按需加载设计

状态：核心实现与自动化验证已完成；真实模型长任务验收待执行。确认日期：2026-09-18。实际交付与边界见《Skill使用与验证说明.md》。

## 1. 目标与范围

将可重复使用的做事方法保存为本地 Skill。即使安装 1000 个 Skill，也不能把全部目录或正文无界注入模型请求。

本期组合三个思路：pi 的正文按需读取、Codex 的目录预算与压缩、maka 的搜索后加载。Skill 的本质是模型可读取的说明与附件；执行继续使用现有 Agent Loop、工具账本和审批机制。

交付范围包含本地发现、启停与固定、显式选择、目录装配、搜索、正文及附件读取、上下文接续和最小可用界面。首个真实验收场景是“按代码检查 Skill 检查当前 Git 改动，并提供问题位置和验证依据”。

暂不做市场、自动下载更新、向量数据库、独立 Skill Agent 或通用工作流引擎。Skill 不保证模型逐步执行正确；强制验收规则仍由程序检查。

## 2. 本地来源和身份

- 项目来源：Session 授权目录快照下的 `.agents/skills/`，主目录优先，关联目录按快照顺序排列。
- 个人来源：默认 `~/.agents/skills/`，允许配置其他明确选定的 Skill 根目录。
- 每个 Skill 以一个含 `SKILL.md` 的目录为单位，可有 `references/`、`scripts/`、`assets/`。
- 第一版只发现 `SKILL.md`，不把任意 Markdown 文件推断成 Skill。找到 Skill 根目录后停止向其内部递归发现其他 Skill。
- 解析 YAML 的 `name`、`description`、`disable-model-invocation`，保留其他兼容元数据。缺少名称、描述或无法解析时不加载，提供诊断。
- 稳定 `ref` 由来源根 ID 与相对 Skill 目录组成，不能只用显示名称充当身份。来源根保存独立 ID，目录移动后需显式重新关联。
- 同名默认优先项目、再个人；同级按根配置顺序及规范化相对路径排序。界面展示胜出来源和被覆盖项，显式选择使用准确 `ref`。

禁用项不进入目录、搜索或加载；`disable-model-invocation` 项不进入模型目录及搜索，但用户可以显式选择。固定只提高目录排序，不能突破预算或权限。

每个 Turn 创建不可变目录快照，避免同一轮内搜索和加载看到不同版本。元信息刷新在下一 Turn 生效；读取正文时校验内容哈希，发现目录版本与文件不一致则返回 `skill_version_changed`，不静默使用新正文。新一轮可刷新后重试。

## 3. 发给模型的内容

### 3.1 自动选择

```text
系统指令：有界 Skill 目录 + 如何搜索和加载
用户消息：检查当前 Git 改动
模型：skill_search({query: "代码检查"})，或直接 skill_read({ref: ...})
Runtime：读取并验证本地资源
工具结果：身份、版本、正文、是否完整、接续游标
模型：根据正文使用现有文件和命令工具
```

目录只包含名称、简短用途、稳定引用，正文通过工具结果进入模型上下文。模型无法凭路径直接访问电脑。

### 3.2 用户显式选择

输入区选择 Skill，或输入 `/skill:名称`，服务端解析为准确 `ref`。同名且不能唯一确定时，返回候选供选择，不自行猜测。

持久化原始用户消息、选择引用及加载结果；组装模型请求时，将已校验正文作为带来源标记的用户级内容注入，不把正文提升为系统指令。UI 显示可展开的 Skill 卡片，不用大段正文替换用户原始输入。

正文放不进本次预算时，只注入准确引用和必须读取的提示，由 `skill_read` 分页加载。不能截断正文后仍标记为“完整加载”。全部指定项加载失败则不请求模型；部分失败在调用前明确告知用户，由用户选择是否继续，不能静默遗漏指定要求。

## 4. 目录预算与降级

初始配置采用以下策略，后续根据验收数据调整，不照搬参考项目的固定数值：

```text
目录目标预算 = min(模型容量 × 2%, 4000 token)
实际目录预算 = min(目录目标预算, 完整请求预算规划器分配的空间)
```

不设置 4000 token 的保底，避免小窗口被目录挤占。模型容量未知时使用可配置的保守预算；无法证明完整请求可发送时明确报错。所有目录、协议说明、工具定义、搜索结果和正文都要计入请求预算。

优先使用模型对应计数器；没有计数器时使用保守估算，标记 `estimated`，不得把字符数当成精确 token。

目录优先级：本次显式选择、用户固定、项目来源、个人来源，同级使用稳定排序。显式选择仍受正文和总请求预算限制。

装配顺序：

1. 去掉禁用、自动调用受限和不符合会话访问边界的条目。
2. 使用紧凑引用；确实需要暴露重复路径时，用根别名，只有计入别名表后仍更省空间才采用。
3. 对过长描述裁剪，标记目录描述不完整，不改变源文件。
4. 在预算内保留有辨识度的简介；压缩后若只剩名称也难以判断用途，将低优先级项移出目录。
5. 仅提示省略数量和搜索入口，不列出所有被省略的名称。

目录为空但存在可搜索项时，仍保留搜索说明与工具。完整库存仅留在本地，不作为工具结果发送。

## 5. 搜索与读取工具

| 工具 | 输入 | 输出与约束 |
|---|---|---|
| `skill_search` | `query`、可选 `limit`、`cursor` | 最多 8 条候选简介，默认结果预算不超过 1000 token，受当前请求剩余预算进一步限制；不返回正文 |
| `skill_read` | `ref`、可选 `resource`、`cursor` | 默认读取 `SKILL.md`，附件相对于 Skill 根；每页默认不超过 2000 token，返回版本、完整性和下一页游标 |

上述数值为第一版可配置默认值，不是模型容量外的额外额度。多工具并行返回共享现有结果总预算，不可每个工具各自用满剩余空间。

搜索先用本地词法排序：名称和标识精确匹配优先，其次名称、描述关键词；中文采用字符片段匹配，不能只按空格分词。相关性同分后再比较固定和来源优先级。使用游标或改写关键词继续搜索，避免只返回固定的前 8 条。

游标绑定目录版本、规范化查询和位置；读取游标绑定资源版本和位置。版本变化返回具体错误，不混合分页结果。模型可以按准确 `ref` 加载未被目录展示的可用 Skill。

正文超长时分页而非静默丢尾部。返回 `complete=false`、`next_cursor` 和继续读取说明；历史记录不能把只读一页标记为完整加载。单文件物理大小、目录扫描数量及读取时间另设可配置硬限制；超过限制产生可见诊断，不声称完整发现。

## 6. 权限与附件

Skill 目录是独立的只读资源边界，不因此成为普通文件工具的可写工作区。读取需同时校验授权来源、准确引用、相对资源路径和解析后的真实路径；拒绝绝对附件路径、`..` 逃逸、符号链接逃逸和循环。

读取 Skill 允许在只读会话执行。Skill 文本、`allowed-tools` 或脚本说明不能授予权限、禁用审批或扩大网络与文件访问范围。

本期脚本通过现有命令工具执行，仅允许会话既有执行边界覆盖的脚本与目标。个人 Skill 附件在工作区外时，允许受控读取，但不自动增加执行权限；需要执行则明确提示将所需脚本纳入已授权项目流程。不得因为加载了 Skill 就自动安装依赖、复制并执行脚本或运行初始化命令。

## 7. 与上下文压缩及恢复衔接

以用户已完成的上下文压缩能力为接入前提。当前 checkout 的上下文文档与源码可能落后，实施前需确认真实实现所在分支和已有端口；不另外创建第二套压缩机制。

保存已加载 Skill 的 `ref`、正文哈希、所属 Turn、显式/自动来源、完整读取状态以及必要的任务接续引用。正文及已读附件保存为会话可引用的版本快照，复用已有历史/Artifact 存储能力，避免每次执行重复复制。

压缩后的处理：

- 重建当前可用的有界目录，不直接沿用过期权限信息。
- 从任务接续信息找出仍在使用的 Skill，记录已完成步骤、剩余要求和对应版本。
- 在预算内恢复所需正文；放不下时保留准确引用，并要求先读取再继续依赖该内容的工作。
- 可恢复的内容快照不代表旧权限继续有效，仍检查当前禁用状态和访问范围。
- 版本发生变化时明确标记，不静默切换到新手册；已结束任务的 Skill 不永久常驻。

Skill 使用本身不建立独立工作流引擎。接续进展复用既有任务笔记；运行事实、权限与读取完整性由程序保存和验证。

## 8. 工程落点与可观测性

| 层次 | 职责 |
|---|---|
| Domain | Skill 身份、来源、版本、启用状态、选择和读取不变量 |
| Application | 发现/搜索/加载/显式调用用例；定义 SkillCatalog、SkillResourceReader 等端口；调用现有预算规划能力 |
| Infrastructure | 文件扫描、YAML 解析、词法检索、版本快照、持久化、Runtime 工具适配 |
| Presentation | 会话可用 Skill 列表、输入区选择与加载卡片、诊断展示；沿用现有工作台组件 |
| Composition | 注册端口与工具，保持内层不依赖具体模型 SDK |

工具仍走现有 `ToolDescriptor`、`ToolExecutionResult` 和 T1/T2 账本。读取与搜索可声明为只读并行工具，预算分配和不可变快照由 Runtime 统一控制。

记录目录总数、展示数、省略数、预算估算、搜索候选数、加载版本、分页状态、失败原因与压缩后重读次数。监控日志不复制正文或用户原始查询；会话内容按既有持久化策略管理。

前端先复用已有输入区、选择器、工具时间线和折叠卡片；展示目录中省略的原因，避免用户误认为文件丢失。实施时先检查共享组件及成熟页面，再在真实客户端验收。

## 9. 实施顺序与验收

分三条可运行的纵向切片，每条同时交付接口、Runtime 接入、界面及必要测试：

1. 发现、准确引用、显式调用、受控读取和结果卡片，跑通代码检查 Skill。
2. 有界目录、路径压缩、中文搜索、分页和 1000 个 Skill 场景。
3. 版本快照、上下文压缩接续、异常恢复和实际长任务验收。

核心验收：

- 安装 1000 个 Skill 时，完整请求不越预算，搜索仍能找到未展示项；固定不能突破上限。
- 用不同模型容量验证目录预算，中文描述和超长路径纳入实际计数或保守估算。
- 显式指定成功时模型收到正确版本正文；失败不伪装为成功，用户原始消息保持可追溯。
- 同名、禁用、仅显式调用项、格式错误和读取失败都有确定行为。
- 搜索验证中文、英文、精确引用、同义表达失配和无结果，建立小规模带预期 Skill 的检索用例集。
- 长正文及附件分页不丢内容、不串版本；分页继续消耗上下文，不能绕过总预算。
- 个人 Skill 可受控读取，但不能借附件路径或脚本执行越过工作区权限。
- 目录扫描过程中修改文件、Turn 中修改正文、压缩后版本变化都不静默混用。
- 多次压缩及重启后，任务目标、正在使用的 Skill 和未完成要求可接续，已完成副作用不重复执行。
- 真实代码检查任务覆盖发现问题、无问题、测试无法运行三种结果，报告必须区分实际验证与推断。

第一版不预设检索准确率或任务成功率已经达标，使用真实验收集记录候选命中、模型加载选择、遗漏检查和上下文成本后再调整。
